# UI con shadcn/ui

Regla del proyecto: **no se construyen componentes visuales desde cero**. Todo sale de shadcn/ui, sus blocks o registries compatibles. El código propio compone y agrega lógica.

Las decisiones que rigen esta página: ADR 007 (shadcn sin componentes propios), ADR 009 (principios de interacción) y ADR 010 (reutilizar patrones de UI). Este documento es el catálogo operativo de esos principios y se lee antes de diseñar una interacción nueva.

## Dónde vive cada cosa

- `packages/ui/src/components/*`: componentes instalados con el CLI (estilo `base-nova`, primitivas `@base-ui/react`).
- `packages/ui/src/components/reui/*`: componentes del registry ReUI (hoy, `event-calendar`, disponible para productos con agenda).
- `packages/ui/src/components/calendar.tsx`: el `Calendar` de shadcn (`react-day-picker`) con sus controles ya traducidos al español, pisables por la prop `labels`.
- `packages/ui/src/styles/globals.css`: tokens y tema.
- `packages/ui/src/hooks/*`: hooks del registry (`use-mobile`).
- `apps/web/components/*`: composiciones propias (formularios, dialogs, listados).
- `apps/web/components/form-dialog-content.tsx`: `FormDialogContent`, el `DialogContent` de los formularios, ver Formularios.
- `apps/web/components/settings/confirm-dialog.tsx`: `ConfirmDialog`, la confirmación de una acción destructiva, ver Formularios.

## Agregar un componente

Siempre desde `apps/web` para que el CLI respete los alias del monorepo:

```bash
cd apps/web
pnpm dlx shadcn@latest add <componente>          # va a packages/ui
pnpm dlx shadcn@latest add @reui/<item>          # registry ReUI
pnpm dlx shadcn@latest add <block>               # los blocks van a apps/web
```

Importar como `@repo/ui/components/<nombre>`.

## Formularios

- Siempre en un pop-up centrado (`Dialog` con `FormDialogContent`, que limita el alto a la pantalla y scrollea solo en vertical), nunca en panel lateral; el único `Sheet` es el menú de navegación en móvil. `react-hook-form` + `zodResolver` con el schema de `packages/domain`; los errores de la API se vuelcan al campo con `showRequestError` (`apps/web/lib/form-errors.ts`).
- Todo pop-up desenfoca el fondo (`dialog-overlay` con `backdrop-blur`), también los anidados (`forceRender` en Base UI).
- Una acción destructiva pide confirmación con `ConfirmDialog` (`AlertDialog` con "Volver" y el verbo de la acción, spinner mientras corre y sin cierre mientras está pendiente).
- Un listado de entidades es un `ItemGroup` de `Item variant="outline"` con `ItemTitle` (+ `Badge`), `ItemDescription` y `ItemActions` con un `DropdownMenu` "Acciones de <entidad>" de trigger `Button variant="ghost" size="icon"`.

## Principios de interacción (ADR 009)

1. Movimiento solo el que traen shadcn/Base UI y `tw-animate-css`, respetando `prefers-reduced-motion`.
2. Toda acción asíncrona deshabilita su control y muestra `Spinner`, sin cambiar el texto del botón.
3. Todo dato asíncrono muestra `Skeleton` del tamaño de lo que va a aparecer.
4. Todo elemento con acción muestra estado hover.
5. Mobile-first: la página nunca scrollea a lo ancho (lo verifica `mobile.spec.ts`).

## Tipografía

Google Sans vía `next/font/google` (`apps/web/lib/fonts.ts`), servida desde el dominio propio; `fonts.spec.ts` verifica que ninguna pantalla pida a Google Fonts. Tema claro y oscuro con `next-themes` (`attribute="class"`).
